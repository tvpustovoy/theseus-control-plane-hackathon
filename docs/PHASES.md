# Две фазы: один процесс и два режима работы

Это роли **внутри продукта**, не обязательно отдельные LLM-сессии. Muse/Argon — разработчики этих частей. В первом прототипе несколько ролей могут быть обычными функциями одного приложения.

| Роль в продукте / разработчик | A · Первичная сборка | B · Инкремент и управление | Передаваемый результат |
|---|---|---|---|
| Приёмщик источников / Muse | Составляет разрешённый реестр; определяет MIME и тип файла; хеширует; фиксирует происхождение | Проверяет новые хеши; повторный файл пропускает; изменённый связывает с предшественником | SourceRecord + SourceDelta |
| Извлекатель / Muse + Meta | Обрабатывает текст, PDF, изображения, аудио/видео подходящим путём; выдаёт наблюдения и утверждения | Обрабатывает только новые/изменённые источники; не пересылает весь архив | ClaimBatch с цитатами/таймкодами и неопределённостью |
| Сборщик модели / Argon | Идентифицирует сущности, связи, временную область; сохраняет кандидатов в MongoDB | Делает версионированный diff, связывает с предыдущими claims и зависимыми объектами | ModelSnapshot / ModelDiff |
| Проверка согласованности / Muse + SubQ | Сначала нормализация и дешёвые проверки, затем подбор пар/пакетов и Snap | Сравнивает новые claims с затронутыми старыми; проверяет межгрупповые пропуски выборкой | ConflictCandidate + маршрутизация, не вердикт истины |
| Deputy CEO / Argon + Fetch.ai | Уточняет назначение, показывает пробелы/конфликты, запрашивает подтверждение исходной модели | Объясняет, что новый материал меняет: цель, обещание, правило, приоритет, инструмент; приносит существенное решение владельцу | DecisionProposal с вариантами и основаниями |
| Исполнитель изменений / Argon | Строит один инструмент из утверждённого контракта | Предлагает патч инструмента и версию навыка/контекста; не меняет собственную власть | ChangeCandidate + diff + development-test results |
| Независимый проверяющий / отдельная сессия | Фиксирует исходный результат и отложенную оценку | Проверяет кандидата на новых случаях, регрессиях и ограничениях | EvaluationReport; разрешение/запрет по заданной политике |
| Управляющий версиями / Argon; интеграцию проверяет координатор | Фиксирует утверждённый baseline | Активирует только прошедшую проверку разрешённую версию, сохраняет возможность отката | ActiveVersion + ActivationReceipt + RollbackReceipt |
| Наблюдатель поведения / координатор специфицирует, Argon реализует | Начинает журнал действий и привязку к целям/правилам | Сравнивает реальное поведение с решением, накапливает гипотезы культуры и контрпримеры | BehaviorEvidence; подтверждение доставки отдельно от исполнения |

## Новый звонок с основателями — пример B, не готовый факт
1. Добавляется разрешённое видео с отметками доступа и источником.
2. Meta извлекает высказывания: «встреча обсуждает X», «участник предложил Y»; отличает предложение от принятого решения.
3. Система связывает их с существующим продуктом и обязательствами. Ошибку атрибуции говорящего оставляет как неопределённость.
4. SubQ проверяет выбранные конфликты с прежними утверждениями. Новая дата не даёт автоматического приоритета.
5. Deputy CEO предлагает владельцу: принять изменение, ограничить область, запросить уточнение или оставить прежнее.
6. Только принятое решение становится входом для изменений кода/плана; неподтверждённое предложение не отменяет обязательств.
7. Проверяем версию и фактическое поведение; сохраняем исходные свидетельства.

## Когда A закончена
Один выбранный процесс, разрешённые источники, проверяемые ссылки на свидетельства, видимые конфликты, утверждённая модель v1 и исполняемый инструмент с исходной оценкой.

## Когда B продемонстрирована
Один новый источник прошёл весь путь до объяснимого изменения, решения человека, испытанного кандидата и принятия/отката. Повторная загрузка не дублирует события. История v1 остаётся доступной.

## Общие ограничения
Неподдерживаемый или повреждённый файл попадает в очередь разбора с причиной. Ошибка извлечения не трактуется как отсутствие фактов. Пересмотрен источник — зависимые выводы помечаются требующими проверки. Гипотеза культуры требует повторений и контрпримеров; событие само по себе не становится нормой.
