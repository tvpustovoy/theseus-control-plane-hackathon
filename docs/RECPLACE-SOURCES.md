## Как показать честность переноса
Argon делает private import manifest: source snapshot/run, список таблиц, схема/типы, количество до/после, хеш каждой экспортированной записи и одинаковый aggregate digest отсортированного мультимножества записей на обеих сторонах. Сохранять дубликаты и null; числа не округлять через JavaScript Number.

Протокол canonicalization/version фиксируется заранее. Это доказательство равенства экспортированных логических записей, не физического файла DuckDB. Сверка до/после должна обнаружить изменение источника во время переноса. Если нет стабильного снимка/согласованного чтения — пометить copy incomplete, не выдавать несогласованный экспорт за полную копию.

В публичный reports/evidence идут только количества, хеши, версия импортера и результат сверки. Payload, переписка, имена/телефоны и локальные private манифесты остаются вне Git, например database/private/.

## Что было с MCP
Функция json_keys отклоняется SQL guard: services/sql_guard.py не включает её в SAFE_FUNCTIONS. Даже вызов на пустом JSON отклонён, тогда как COUNT(*) семи raw-таблиц работает. MCP скрывает подробности ошибки общей строкой. Это **не доказательство отсутствия доступа к данным**; исправлять права для обхода json_keys не нужно. Сам payload ещё не выгружен этой сессией.

MCP ограничивает ответ 1000 строками и сериализованным объёмом 50000 символов; клиент также имеет суточный лимит. Экспортёр обязан учитывать штатные лимиты, не отключать их и не менять права молча. Если полный экспорт не помещается в выданные права/лимиты, сообщить владельцу/ответственному за доступ до продолжения. Не использовать get_source_document с обрезанным текстом как полную raw-копию.

## Индекс источников после копии
Из raw_records строим sources, затем source_chunks, внутри MongoDB. Без LLM и без смыслового изменения: распаковать структуру записи, сохранить полный исходный текст, атрибуты и raw_record_ids.

Для восстановления прежних классификаций допустимо сверить core.DOCUMENTS (RAW_REF, BASKET, SOURCE_KIND, FILE_FORMAT, DAY, BODY_TEXT и признаки обрезки) и core.SRC_DOCUMENTS/SRC_CHUNKS/SRC_UTTERANCES как **производные справочники**. Они не заменяют raw-слой и не считаются результатом нового Meta-извлечения. Внутренние ключи JSON V ещё не проверены: Argon устанавливает mapping на реальных разрешённых записях, не угадывает поля.

Тексты продаж/переговоров, нормативка/скрипты, голос основателей и структурированные CRM-события маршрутизируются по инструкции Muse. Новое видео добавляется отдельным источником позднее, не подменяет старый raw.
